# Checkpoint 7: Mission Reflection

Throughout this laboratory activity, I learned how to monitor Linux system resources, manage Docker containers, and troubleshoot application problems.

First, checking the host server's resources is important even when containers are running perfectly because containers still depend on the host's CPU, memory, and disk space. If these resources become insufficient, applications may slow down or stop working properly. Monitoring the host helps prevent performance problems before they affect users.

Second, the `docker logs` command helps investigate login problems by showing messages generated by a container. These logs may reveal application errors, failed authentication attempts, database connection problems, or other issues. By examining the logs, an engineer can identify possible causes and determine what needs to be fixed. However, the logs only show information that the application or container actually records.

Third, monitoring logs and metrics have different purposes. Logs provide detailed records of events, errors, and requests that help engineers understand what happened. Metrics provide numerical measurements, such as CPU usage, memory consumption, and resource utilization over time. Both are important because logs help explain problems, while metrics help identify performance changes and resource issues.

Fourth, large enterprise companies can use monitoring tools such as Prometheus and Grafana to manage thousands of containers. Prometheus collects and stores metrics from monitored systems, while Grafana displays the collected data through dashboards and graphs. These tools help engineers monitor multiple containers, identify unusual resource usage, and detect possible problems more efficiently.

Finally, this laboratory improved my ability to troubleshoot Linux environments. I learned to check system resources using Linux commands, deploy and test an Nginx container, identify a 404 error, inspect container logs, and monitor CPU and memory usage using Docker. I now understand that troubleshooting requires observing system behavior, examining evidence, and identifying the possible cause before applying a solution. These skills will help me manage and maintain applications in future cloud computing activities.
